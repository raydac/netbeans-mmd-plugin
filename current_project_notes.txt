## 2. Architecture & Technical Discoveries
- Java `Printable` user space is 1/72 inch. Printer `Graphics2D` already includes a DPI scale (often 300/72). Pre-rendering a `BufferedImage` at `PageFormat.getImageableWidth()` pixels is ~72 DPI and looks soft when the driver upscales it. Draw vectors (or the original image with `AffineTransform`) in that user space so the printer samples at device resolution.
- Print tiles must `clip` the sheet in page space *before* translate/scale. Affine transform then maps that clip into map space, so `getClipRect()` still culls later tiles. Never `setClip` after translate: that replaces the preview/viewport clip (IntelliJ HiDPI wrappers treat it as device space) and topics paint on the dialog around the page. Preview 10–200% is view-only and must not re-layout or re-paginate.
- IJ: settings stay an `applicationService` (`MindMapApplicationSettings`); removed deprecated `preload="true"` so the marketplace verifier is satisfied — service still initializes lazily on first `getService`/`getInstance` (plugins registered in the constructor).
- Do not put `<fileType>` as a root `<idea-plugin>` child. 222 PluginManager treats that as `Unknown element: fileType` (`XmlReader.readRootElementChild`). It must live under `<extensions defaultExtensionNs="com.intellij">`.
- `fileType` attributes that exist on 222: `name`, `implementationClass`, `fieldName`, `language`, `extensions`. `name` must match `FileType.getName()`, `language` must match `MMLanguage` id `NBMindMap`.
- `MindMapFileType` constructor is private; `fieldName="INSTANCE"` is required.
- Latest IntelliJ New File popup lists file types from the declarative EP and Files-category templates. `FileTypeFactory` is deprecated and ignored or unloaded there, so MMD vanished from New while the editor could still open existing files. Do not also ship a Files-category `.ft` when `CreateMindMapFileAction` is in `NewGroup` — that is the duplicate New item (custom dialog vs generic template dialog).
- `CreateFileFromTemplateAction` on 222: constructor `(text, description, icon)`, `buildDialog(Project, PsiDirectory, Builder)`, `getActionName(...)`. Platform `createFile` uses `getInternalTemplate`; our override uses `findInternalTemplate` / Files / Other and a default MMD body so latest IDEs do not throw `Template not found`.
- Panel shortcuts are KeyListener + `MindMapPanelConfig` maps, not panel ActionMap/InputMap. Host IDEs must not assume Swing Action registration on the panel.
- `MindMapPanel` applies first-open root centering synchronously in layout/`setBounds`/`addNotify` when hosted in a `JViewport`. Do not use `invokeLater` after paint — that is the visible jump (and FlatLaf smooth-scroll animates it). Undo/redo `setModel` does not re-request centering; import and first document load call `requestRootCenteringInViewport()`.
- `MindMapPanel.paintComponent` must not call `paintChildren`; Swing paints children after the component. Overlays (drag ghost, rubber-band, birds-eye) stay in `paintComponent` on a `g.create()` copy so the title editor still paints last. `calculateSizeOfMapInPixels` and layout-from-`getGraphics()` always work on a copy and dispose only that copy.
- Panel input listeners are registered in the constructor (not `invokeLater`) and removed in `dispose()`. Hosts that constructed a panel and immediately disposed it previously could still receive late listener registration.
- Title editor Enter end-edit must use keyPressed/keyReleased (`getKeyCode()`); KEY_TYPED has `VK_UNDEFINED` so typed-path end-edit was dead.
- Shift+Enter next-line intentionally handled in both typed and released for RUS layout under Linux/IDEA.
- scia-reto: tree model notifications already use `Utils.safeSwingCall`; subtree load mutates `children` off EDT but listeners are notified on EDT via `notifyProjectStateChanged` / `invokeLater` fireNotifySubtreeChanged.
- scia-reto: `MindMapPanelConfig.getScaleModifiers()` still uses old `KeyEvent.CTRL_MASK` style — keep `getModifiers()` when matching wheel/scale shortcuts against that config.
- Encrypted MMD notes live in the model as ciphertext + `extras.note.encrypted`; AES is only in Swing `CryptoUtils` (AES-256-ECB PKCS5, SHA-256 prefix). The skill `crypto.py` and `js-viewer/mmd-viewer.js` reimplement that so agents/browsers can decrypt after the user supplies the password.
- `js-viewer` layout follows the Swing panel: root children with `leftSide=true` go left, others right; first-level connectors are cubic curves; deeper connectors are orthogonal via the collapsator; collapse is view-only (not written back). Topic text, emoticons, extra icons, and embedded `mmd.image` pictures share one vertical midline (picture sits after the emoticon, before the title). Keyboard focus matches the Swing panel: from the root, left/right select the first child on that side; on a branch, left/right move toward the root or into the first child (unfolding if needed), and up/down stay among siblings (same side at the first level). Selection pans using layout bounds, not SVG getBoundingClientRect (icon sprites overflow their tile). Click, drag, and keyboard focus do not open the notes panel. Double-click is detected from two still clicks on the same topic (native `dblclick` is unreliable after `setPointerCapture` for pan). Double-click a topic opens notes in every `notesLayout`; double-click a LINK/FILE/TOPIC/IMAGE extra still follows that extra. Jump links are a dashed line from the source center to a filled arrowhead on the destination edge (`drawArrowToDestination`). Extra URL/path hints overlay the stage so they do not resize the toolbar. File extras open only as http(s) resolved against the map or page (browsers cannot open arbitrary local paths). Pointer Events drive pan/pinch when present; otherwise mouse and touch. Avoid CSS flex `gap` (older iOS Safari ignores it on flex). Drag past a small threshold pans even if the press started on a topic; a still click still selects. Focus is a dashed orange rectangle around the topic (`selectLineWidth` 3, `selectLineGap` 5, dash `3w,w`), drawn in an overlay after topics like Swing `drawSelection`, not a thicker topic border. Notes layout is `notesLayout`: `auto` (wide side column; ≤720px portrait bottom sheet / landscape right overlay), `landscape`, `portrait`, or `modal` (centered dialog, backdrop click or Escape closes). Docked notes use `flex: 0 0 auto` so the auto/landscape column is not squeezed to nothing.
- mind-map-model `Topic.parse` is a private `TopicParser`; extras passed to the `Topic` constructor now follow the same attach lifecycle as `setExtra`.
- NetBeans user-dir MIME resolver (`FileUtil.setMIMEType`) has highest priority. After the plugin is disabled, opening `.mmd` can persist `mmd → text/plain`; the declarative `@MIMEResolver.ExtensionRegistration` without `position` sits at `Integer.MAX_VALUE` and loses. Reclaim with `FileUtil.setMIMEType("mmd", MIME)` on start, `DataLoaderPool.setPreferredLoader(fo, null)` + `DataObject.setValid(false)` for stuck objects, and retry the closed text editor if it vetoes invalidation. Do not walk every open project on unrelated TopComponent close (EDT freeze). Clear the user mapping on `@OnStop` if it still lists `.mmd` for our MIME.
- NB refactoring file I/O: wait for `FileObject.lock()` with a bounded retry (`FileObjectLocks`, 20 × 500 ms) and throw on interrupt/timeout. A failed link rewrite discards the cached `MindMap` so undo uses the snapshot, not a half-mutated model.
- IJ Structure view: custom `FileEditor` with `HIDE_DEFAULT_EDITOR` only shows Structure if `FileEditor.getStructureViewBuilder()` or `lang.psiStructureViewFactory` is set. Tree is the live `MindMap` topic graph (position paths as node ids), not PSI `PsiTopic` (whose `getName()` is the whole subtree text). Extra `MindMapListener` on the panel must return `true` from `allowedRemovingOfTopics` (listeners are ANDed). Do not `removeMindMapListener` after `MindMapPanel.dispose()` (`assertNotDisposed`). `setModel(map)` does not notify listeners — PSI tree changes cover document reloads.
- IJ Gradle 2.x: `org.jetbrains.intellij` 1.x cannot resolve the 2024.2+ module layout. `idea-mindmap` now uses `org.jetbrains.intellij.platform` 2.19.0 with Gradle 9 (`gradle9` in `idea-mindmap/pom.xml`). Platform is `intellijIdeaCommunity('2024.2.5')` with `useInstaller = false` (multi-OS archive, like 1.x). `untilBuild = provider { null }` keeps no upper IDE cap. `build` depends on `buildPlugin` so Maven `build` still produces `build/distributions/*.zip`. Compile language level is 21 (2024.2 JBR). Gradle 9 needs `settings.gradle`.

## 5. Known Issues & Limitations
- js-viewer is read-only: collapse/zoom are session-only; topic images are displayed but cannot be added or removed.
- Sandbox/build target is `IC-2024.2.5` (`since-build` 242.20224.159). Latest-IDE New File UI still wants a smoke check after install.
- `MindMapPanel.getModel()` throws if no model has been set; IJ editor now installs a default empty map immediately after construction.
- `processPopUpForShortcut` with empty selection only selects root and does not open the menu; `VK_CONTEXT_MENU` always opens — intentional difference, leave unless UX change is requested.
- scia-reto assembly (non-script): all descriptors still share `<id>withjre_windows</id>`; `mac-nojre.xml` exclude typo `icon.svgicns`; linux fileSets omit explicit `fileMode` 0755; `mac-aarch64/` tree unused (packs from `mac/`).

Early console is quiet because JUL starts at WARNING until after splash. `StartupWMClass=scia.reto.editor` does not match real WM_CLASS `SciaReto`.

## 8. User Advice and Recommendations
- Keep File | New compatibility with latest IntelliJ and with previous versions back to 2024.2 (242.20224.159).
- Do not break public APIs of mind-map-swing-panel when cleaning internal Swing action handling.
- Do not break public APIs of mind-map-model (signatures, Serializable UIDs, logger SPI) when fixing internals.
- Restrict scia-reto Swing audits/fixes to the `scia-reto` submodule unless the user widens scope.
- js-viewer notes panel: user asked for double-click (not click/focus/drag) to open notes so selecting and panning stay unobstructed. Extra icons still activate on double-click of the icon itself.
- For user-facing fixes and changes, update both root `README.md` (Changelog section) and `changelog.txt`.
- **README.md changelog:** keep it short — **one or two lines per change**, a headline a user can scan. Rephrase long bullets; do not paste the full technical story there.
- **changelog.txt:** the full change description lives here (details, edge cases, issue numbers, how it behaves). README can point at it; do not duplicate the long form in README.
- When a common change affects the shared mind-map panel and therefore the IDE plugins (changelog `ALL:` items), also update IntelliJ IDEA `mind-map/idea-mindmap/resources/META-INF/plugin.xml` `<change-notes>` for the current SNAPSHOT/unreleased version. That is the marketplace changelog IDEA users see; keep it closer to the short README form than to `changelog.txt`.
- When an encrypted MMD note is needed for work, ask the user for the password and decrypt with the skill `crypto.py` scripts; do not guess the password or treat ciphertext as text.
- Ship agent skills in repo `skills/` for users to copy; do not keep them only under `.cursor/skills/`. Project slash commands that activate those skills may live in `.cursor/commands/`.
- When documenting Java architecture for later agents, mark sources with `@MmdFile` / `@MmdTopic` (`skills/mmd-annotations`, `/mmd-annotations:setup` then `/mmd-annotations:mark`) and let the processor generate maps; do not freehand those `.mmd` files. The skill must first attach the annotation artifacts to the user’s module and audit compiler options (`-proc:none`, processor path, `-Ammd.*`).
