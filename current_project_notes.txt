## 2. Architecture & Technical Discoveries
- Java `Printable` user space is 1/72 inch. Printer `Graphics2D` already includes a DPI scale (often 300/72). Pre-rendering a `BufferedImage` at `PageFormat.getImageableWidth()` pixels is ~72 DPI and looks soft when the driver upscales it. Draw vectors (or the original image with `AffineTransform`) in that user space so the printer samples at device resolution.
- IJ: settings stay an `applicationService` (`MindMapApplicationSettings`); removed deprecated `preload="true"` so the marketplace verifier is satisfied — service still initializes lazily on first `getService`/`getInstance` (plugins registered in the constructor).
- Do not put `<fileType>` as a root `<idea-plugin>` child. 222 PluginManager treats that as `Unknown element: fileType` (`XmlReader.readRootElementChild`). It must live under `<extensions defaultExtensionNs="com.intellij">`.
- `fileType` attributes that exist on 222: `name`, `implementationClass`, `fieldName`, `language`, `extensions`. `name` must match `FileType.getName()`, `language` must match `MMLanguage` id `NBMindMap`.
- `MindMapFileType` constructor is private; `fieldName="INSTANCE"` is required.
- Latest IntelliJ New File popup lists file types from the declarative EP. `FileTypeFactory` is deprecated and ignored or unloaded there, so MMD vanished from New while the editor could still open existing files.
- `CreateFileFromTemplateAction` on 222: constructor `(text, description, icon)`, `buildDialog(Project, PsiDirectory, Builder)`, `getActionName(...)`. `createFile` resolves the template via `getInternalTemplate`, which also falls back to Files-category templates.
- Panel shortcuts are KeyListener + `MindMapPanelConfig` maps, not panel ActionMap/InputMap. Host IDEs must not assume Swing Action registration on the panel.
- `MindMapPanel` applies first-open root centering synchronously in layout/`setBounds`/`addNotify` when hosted in a `JViewport`. Do not use `invokeLater` after paint — that is the visible jump (and FlatLaf smooth-scroll animates it). Undo/redo `setModel` does not re-request centering; import and first document load call `requestRootCenteringInViewport()`.
- Title editor Enter end-edit must use keyPressed/keyReleased (`getKeyCode()`); KEY_TYPED has `VK_UNDEFINED` so typed-path end-edit was dead.
- Shift+Enter next-line intentionally handled in both typed and released for RUS layout under Linux/IDEA.
- scia-reto: tree model notifications already use `Utils.safeSwingCall`; subtree load mutates `children` off EDT but listeners are notified on EDT via `notifyProjectStateChanged` / `invokeLater` fireNotifySubtreeChanged.
- scia-reto: `MindMapPanelConfig.getScaleModifiers()` still uses old `KeyEvent.CTRL_MASK` style — keep `getModifiers()` when matching wheel/scale shortcuts against that config.
- Encrypted MMD notes live in the model as ciphertext + `extras.note.encrypted`; AES is only in Swing `CryptoUtils` (AES-256-ECB PKCS5, SHA-256 prefix). The skill `crypto.py` reimplements that in stdlib Python so agents can decrypt after asking the user for the password.

## 5. Known Issues & Limitations
- Sandbox/build target remains `IC-222.4554.10`; latest-IDE New File UI cannot be verified in that sandbox.
- `MindMapPanel.getModel()` throws if no model has been set; IJ editor now installs a default empty map immediately after construction.
- `processPopUpForShortcut` with empty selection only selects root and does not open the menu; `VK_CONTEXT_MENU` always opens — intentional difference, leave unless UX change is requested.
- scia-reto assembly (non-script): all descriptors still share `<id>withjre_windows</id>`; `mac-nojre.xml` exclude typo `icon.svgicns`; linux fileSets omit explicit `fileMode` 0755; `mac-aarch64/` tree unused (packs from `mac/`).
- AppImage: Linux `Taskbar API is not supported` at start is expected and does not block the GUI; packaging (AppRun/desktop/JRE/`libawt_xawt`) is fine for GUI. Early console is quiet because JUL starts at WARNING until after splash. `StartupWMClass=scia.reto.editor` does not match real WM_CLASS `SciaReto`.

## 8. User Advice and Recommendations
- Keep File | New compatibility with latest IntelliJ and with previous versions back to 2022.2.5 (222.4554.10).
- Do not break public APIs of mind-map-swing-panel when cleaning internal Swing action handling.
- Do not break public APIs of mind-map-model (signatures, Serializable UIDs, logger SPI) when fixing internals.
- Restrict scia-reto Swing audits/fixes to the `scia-reto` submodule unless the user widens scope.
- For user-facing fixes and changes, update both root `README.md` (Changelog section) and `changelog.txt`.
- When a common change affects the shared mind-map panel and therefore the IDE plugins (changelog `ALL:` items), also update IntelliJ IDEA `mind-map/idea-mindmap/resources/META-INF/plugin.xml` `<change-notes>` for the current SNAPSHOT/unreleased version. That is the marketplace changelog IDEA users see; do not leave it empty when README/`changelog.txt` already list shared panel/plugin behavior.
- When an encrypted MMD note is needed for work, ask the user for the password and decrypt with the skill `crypto.py` scripts; do not guess the password or treat ciphertext as text.
- Ship agent skills in repo `skills/` for users to copy; do not keep them only under `.cursor/skills/`.
